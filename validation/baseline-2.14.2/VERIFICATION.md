# ClipShelf 2.14.2｜操作修補與測試結果

已完成原地編輯、焦點與複製重排的局部修補，建立 Windows x64 安裝包。Windows 原生操作與實際升級尚未驗證；本報告不將模型／建置／封裝結果當成滑鼠鍵盤驗收。

## 來源與觀察

使用指定 Drive 工程資料夾中已交付的 ClipShelf-2.14.1-Source.zip，ID 1lWKDk2pqgrES5dDRRslQKKRzhXSYcGx5，SHA-256 d9fcd2569ffd9e270b1a3cf8d477d4e4ba2e6ebd9657cceaf784034d7daf4ab7；重新查詢名稱、大小與修改時間均與交付紀錄相符。本機使用該已逐位元組核對的原始碼包另建 v2.14.2 工作副本。

使用者錄影 ClipShelf.UI_THCQk6UJw6.mp4（135.7 秒，1132×930）顯示：選取後按 Delete 正文不變、文字單擊後使用次數／時間變動並重排、文字旁空白提示框，以及切換資料夾後仍出現上一個未儲存草稿的確認。畫面沒有清楚區分唯讀選取與正文編輯模式，因此不能把每一次 Delete 的畫面直接判定為已進入正文編輯；本次一併修正入口、狀態顯示與輸入接線。

## 實際修補

- 卡片右上新增小型正文鉛筆；標題旁鉛筆仍只改標題。原右鍵／更多選單保留，正文右鍵統一由文字框處理，避免兩個入口互相干擾。
- 原文字 TextBox 直接綁定 IsTextReadOnly。正文有焦點時，Delete／Backspace、Ctrl+V／Ctrl+X 或文字輸入會先開始草稿，再交給原生文字控制處理；保留選取範圍。尚未開始編輯的 Enter／Ctrl+Enter 沿用原貼上／複製快捷鍵，編輯中才轉為換行／儲存。Ctrl／Shift 卡片多選模式不會因文字輸入自動進入修改。
- 編輯中的正文上方顯示狀態、儲存、取消。Ctrl+Enter 儲存正文、Enter 換行、Esc 取消；標題 Enter 儲存／Esc 取消。沒有新增卡片底部的編輯文字或複製按鈕。
- 文字單擊只複製，不再同步展開卡片。複製更新使用時間、次數與歷史狀態並保存，但不重建／重排目前列表；後續切換區域或擷取仍依使用時間排序。完整閱讀改走既有更多選單的「展開全文預覽」，收起控制保留。
- 對已實現且可見的編輯框，不再無條件 ScrollIntoView；外層列表忽略可見文字框的整張卡片帶入請求，內層文字捲動仍由 TextBox 處理。原地焦點等選單關閉後再恢復，不在選單開啟時搶焦點。
- 移除正文 ToolTip，避免 Note／SearchExcerpt 為空時仍彈出空白小框。標題及功能按鈕的有效提示仍保留。
- 切換其他卡片、資料夾／內容類型前先處理草稿；取消資料夾切換時恢復原選擇。編輯期間的外部剪貼資料仍保存並延後重建列表。
- 模型忽略重複設定編輯狀態與相同草稿的通知，減少文字綁定回寫造成的多餘更新。

Core/WPF 分離、資料 schema、分類、收藏、Safe Delete、備份／匯入、去重與原使用者資料路徑沿用基準。沒有恢復 OCR。

## 已驗證的範圍

- .NET SDK 8.0.425；Core 與 WPF Windows x64 自含發佈成功，版本 2.14.2.0。
- 40 項資料、模型與編輯服務檢查通過：原 36 項，加上 4 項唯讀綁定通知、重複通知隔離、草稿回寫及結束編輯狀態測試。直接使用正式模型／編輯服務；未模擬成原生鍵鼠操作。
- NSIS 3.09 amd64 Unicode 生成安裝包；29 項離線封裝檢查通過，解開後的 930 個 payload 檔案逐檔 SHA-256 與發佈目錄相符。
- 安裝腳本與原 v2.14.0 在版本字串正規化後相同；解除安裝僅刪程式檔，程式與資料路徑分離。這是靜態程式檢查。
- Core、設定、儲存、備份與 Shared 程式相對 v2.14.0 保留，僅 Core 診斷更新版本字串。
- WPF XAML 通過編譯；文字框、編輯列與預覽／圖片處在獨立 Grid row。編輯列在正文上方，未新增底部編輯／複製按鈕。
- 完整 Source.zip 解壓完整性及每一個封裝成員位元組核對通過。精確檔案數、大小、SHA-256、Drive 連結和重新下載驗證狀態見版本交付清單。

依既有 BUILD_EXE／BUILD_SETUP 配置在 Linux 使用等價 publish 和 NSIS 參數建置；Windows .cmd／PowerShell 啟動器未在 Windows 執行。原 v2.14.1 的測試與交付紀錄在 validation/baseline-2.14.1，不能作為此次結果。

## 尚未驗證

v2.14.2 的真實 Delete／Backspace、滑鼠選取、直接輸入、中文 IME、原生復原、右鍵焦點、捲動／虛擬化、高 DPI、全域快捷鍵，以及 Windows 原生安裝／升級與實際保留使用者資料均未實測。主機先前明確阻擋 Wine 所需 socket，本輪未在條件未改變時重試，也未把舊版的執行證據當成新版通過。

使用者錄影是 v2.14.1 的問題證據，不是 v2.14.2 已修好的實機證據。

## 使用方式

先從系統匣退出舊 ClipShelf，再執行 ClipShelf-2.14.2-Setup.exe。不需先解除安裝、不需自行編譯或重設剪貼資料。原地更新的程式邏輯沿用原版：程式在 %LOCALAPPDATA%\Programs\ClipShelf，資料在 %LOCALAPPDATA%\ClipShelf。

首次操作可直接選取正文後按 Delete，或按右上正文鉛筆；編輯時看正文上方的儲存／取消列。v2.14.0 與 v2.14.1 的安裝包／原始碼均保留，未覆蓋。
