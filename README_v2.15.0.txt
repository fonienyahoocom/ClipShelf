ClipShelf 2.15.0 — 雙模式剪貼簿 Windows x64 候選交付版

安裝與更新
Windows 10/11 64 位元。執行 ClipShelf-2.15.0-Setup.exe，不需另外安裝 .NET。
更新前先從右下角系統匣「離開 ClipShelf」退出舊版，再安裝；只關閉視窗不等於退出。
可直接原地升級，不必先解除安裝。建議升級前先在舊版做一次完整備份。
程式：%LOCALAPPDATA%\Programs\ClipShelf；個人資料：%LOCALAPPDATA%\ClipShelf。
安裝與解除安裝不清除個人資料。此包未簽章，Windows 可能顯示發行者未知。

快捷選取模式
Ctrl+~（Ctrl 加反引號／波浪鍵，不必按 Shift）開啟／收合獨立的小視窗。
預設約 440 × 570，約十筆紧湊摘要；拖動標題列移動、邊框調整大小，記住位置與尺寸。
直接輸入搜尋；空白分隔關鍵字，所有關鍵字皆需符合。搜尋文字、標題、備註、來源及檔名。
↑／↓ 選取；Enter 貼上並收合；Esc 只收合；Ctrl+C 只複製，不送出貼上。
Shift+Enter 對文字送出純文字貼上。ClipShelf 現有文字歷史本來就只保存純文字，兩者結果相同。
單擊只選取；雙擊列才貼上；F3 開啟全文預覽；圖片有縮圖、檔案有類型摘要。
一次最多顯示 1000 個搜尋結果；搜尋仍涵蓋全部有效最近紀錄。清單採虛擬化，非建立整庫卡片。
視窗開啟期間保留排序；新擷取紀錄加在尾端，重新開啟時再按最近使用排序。
開啟前的外部視窗會作為貼上目標；內容寫入剪貼簿後恢復其焦點，再送出 Ctrl+V。
請先放開快捷鍵／Shift。目標已關閉、焦點被 Windows 拒絕或權限不一致時，顯示原因；可 Ctrl+C 後手動貼上。
Windows 接收鍵盤輸入不代表每個應用程式必定接受貼上；編輯位置及目標程式行為需實機確認。

完整管理模式
快捷視窗右上「完整管理」；系統匣與桌面浮動圖示右鍵也有「開啟完整管理」。
完整管理左上「快捷選取」立即切换到小視窗；浮動圖示左鍵預設開啟快捷選取。
管理模式原有 A 標準／B 緊湊卡片密度切換仍獨立存在，不是兩種工作模式的切換。
保留歷史、收藏、資料夾、分類、搜尋、多選、編輯文字、標題、局部複製及原有備份／匯入。
正文鉛筆進入原地編輯：Enter 換行、Ctrl+Enter 儲存、Esc 取消。
標題鉛筆：Enter 儲存、Esc 取消；清空名稱回到自動摘要。
切到快捷視窗不重設管理視窗選取、捲動、A/B 檢視或編輯草稿。
「視窗切換模式」仍控制工作列／Alt+Tab／不干擾行為，與雙模式用途分開。

快捷鍵衝突
若 Ditto 或其他程式佔用 Ctrl+~，系統匣會提示註冊失敗。
右鍵系統匣 → 完整管理 → 設定，可改用 Ctrl+Alt+V 或 Ctrl+Alt+Q；同樣檢查註冊結果。
不註冊 Ctrl+Shift+F8，也不自動搶奪其他程式的快捷鍵。

常駐與資料保護
Core 與 WPF 仍為兩個程序；WPF 初始化後隱藏常駐，不再於 45 秒／300 秒退出。
快捷視窗在第一次使用時初始化，後續重用；長時間隱藏不應重新冷啟動 WPF。
隱藏時略過重複附件全文掃描，無新增滑鼠輪詢或全域低階滑鼠 Hook。
真正退出會先檢查儲存及草稿；保存失敗時取消退出，不強殺程序。
沿用既有 fail-closed 載入：無法確定 history.json 狀態時停止載入，不能當成空白覆寫。
內部複製使用剪貼簿序號識別，避免自家寫入再成為重複歷史。
Safe Delete／復原／永久刪除及匯入 merge 語義保留。OCR 已移除，不重新加入。

驗證狀態
Windows x64 自含執行環境建置及 NSIS 封裝已完成；64 項模型／資料自動化檢查通過。
4 項實際 IPC 自動化測試被 Linux host 的 socket 權限阻擋，尚未通過實際傳輸驗證。
Windows 原生安裝／升級、Edge／Notepad++／Obsidian 貼上、IME、DPI、多螢幕、浮動選單點外關閉仍待實機確認。
常駐 CPU、記憶體、1／10／30 分鐘喚醒延遲尚未測量；不能宣稱已達暖機 P95 <250ms。
程式將 Core 熱鍵請求到 WPF ContextIdle 的耗時記錄於 %LOCALAPPDATA%\ClipShelf\diagnostics\picker-wake.csv。
原始碼包 Diagnostics\Measure-Wake.ps1 可在 Windows 執行重複熱鍵、1／10／30 分鐘隱藏及資源採樣；本輪未執行。
完整測試邊界與回退方法見更新說明及版本交付清單。

再次建置
開發電腦需 .NET 8 SDK 與 NSIS 3.x；執行 BUILD_EXE.cmd，再 BUILD_SETUP.cmd。
Source 包保留完整歷史工程文件；validation\baseline-2.14.2 為舊版證據，不可當成 2.15.0 測試結果。
